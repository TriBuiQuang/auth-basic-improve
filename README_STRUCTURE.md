## File-by-File Breakdown

### `src/index.ts` — Main Entry Point

**Purpose**: Library entry point for `import authBasicImprove from "auth-basic-improve"`.

**Exports**:
- `export * from "./app"` — re-exports everything from `app.ts`
- `export default authBasicImprove` — default export (namespace import from `app.ts`)

**Dependencies**: `./app`

---

### `src/app.ts` — Module Aggregator

**Purpose**: Aggregates and re-exports the core `auth` module from `basicAuth/`.

**Exports**:
- `export { auth }` — re-exports the `auth` namespace from `./basicAuth/index`

**Dependencies**: `./basicAuth/index`

---

### `src/basicAuth/index.ts` — Core Parser

**Purpose**: The heart of the library. Implements the RFC-compliant Basic Auth parser.

**Key Functions**:

| Function | Signature | Description |
|----------|-----------|-------------|
| `parse(str: string)` | `Credentials | undefined` | Parses a base64-encoded Basic Auth string directly. Returns `{ name, pass }` or `""` on failure. |
| `auth(req: Request)` | `Credentials | undefined` | Extracts the `Authorization` header from an Express `Request` and passes it to `parse()`. |
| `getAuthorization(req)` | `string` | Internal helper: reads `req.headers.authorization`. |
| `decodeBase64(str)` | `string` | Internal helper: decodes base64 to UTF-8 string. |

**Regular Expressions**:

| Regex | Purpose |
|-------|---------|
| `CREDENTIALS_REGEXP` | Matches `Basic <base64string>` pattern (case-insensitive "Basic"). |
| `USER_PASS_REGEXP` | Splits the decoded string into `userid:password`. |

**Interfaces Used**:
- `Credentials` — `{ name: string; pass: string }`
- `IRequestHeaderAuthorization` — `Request` with `headers: { authorization: string }`

**Throws**:
- `TypeError("argument req is required")` — when `req` is `undefined` or not an object.

---

### `src/expressBasicAuth/index.ts` — Express Middleware

**Purpose**: Builds an Express.js authentication middleware with configurable options.

**Key Functions**:

| Function | Signature | Description |
|----------|-----------|-------------|
| `buildMiddleware(options)` | `(req, res, next) => void` | Factory function that returns an Express middleware. |
| `safeCompare(userInput, secret)` | `boolean` | **Static method** on the middleware: timing-safe string comparison using `crypto.timingSafeEqual`. |
| `ensureFunction(option, defaultValue)` | `() => T` | Internal helper: normalizes options to a function (sync). |

**Middleware Options** (`IbuildMiddleware`):

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `challenge` | `boolean` | `false` | When `true`, sets `WWW-Authenticate` header on 401 responses. |
| `users` | `Record<string, string>` | `{}` | Static username→password map. Uses `safeCompare` for each pair. |
| `authorizer` | `function` | — | Custom sync validation: `(username, password) => boolean`. Overrides `users`. |
| `authorizeAsync` | `boolean` | `false` | When `true`, calls authorizer with a callback: `(username, password, cb)`. |
| `unauthorizedResponse` | `unknown` | `""` | Custom 401 body: string, JSON object, or `(req) => string`. |
| `realm` | `string \| function` | `undefined` | Custom realm string or `(req) => string` for `WWW-Authenticate` header. |

**Middleware Flow**:

```
Request
  │
  ▼
auth(req) → parse Authorization header
  │
  ▼
Is auth valid? ──No──→ unauthorized() → 401 response
  │
 Yes
  ▼
Attach req.auth = { user, password }
  │
  ▼
Is async? ──Yes──→ authorizer(name, pass, cb) → cb(err, approved)
  │
 No
  ▼
authorizer(name, pass) → boolean
  │
  ▼
Approved? ──No──→ unauthorized() → 401 response
  │
 Yes
  ▼
next()
```

**Security Features**:
- `safeCompare` uses `crypto.timingSafeEqual` to prevent timing side-channel attacks.
- Compares both username and password buffers with length verification.

### `tests/unit/basicAuth.test.ts` — Unit Tests

**Tests for `parse(string)`**:
- Undefined input → returns `""`
- Malformed string → returns `""`
- Malformed scheme (e.g., `basic_...`) → returns `""`
- Malformed credentials → returns `""`
- Valid credentials → returns `{ name, pass }`
- Empty password → `{ name: "foo", pass: "" }`
- Empty userid → `{ name: "", pass: "pass" }`
- Empty userid + password → `{ name: "", pass: "" }`
- Colon in password → correctly splits at first `:`

**Tests for `auth(Request)`**:
- Missing `req` argument → throws `TypeError`
- No `Authorization` header → returns `""`
- Malformed header → returns `""`
- Valid credentials → returns `{ name, pass }`

### `tests/integration/expressBasicAuth.test.ts` — Integration Tests

Uses Express + `supertest` to test full HTTP requests.

**Test Scenarios**:

| Route | Middleware Config | Tests |
|-------|-------------------|-------|
| `/static` | `users: { Admin: "secret1234" }` | Missing header, wrong creds, correct creds |
| `/custom` | Custom sync authorizer | Prefix-based validation |
| `/custom-compare` | `safeCompare` authorizer | Exact match (not prefix) |
| `/challenge` | `challenge: true` | `WWW-Authenticate` header present on 401 |
| `/realm` | `challenge: true, realm: "test"` | Custom realm in header |
| `/realmfunction` | `challenge: true, realm: () => "bla"` | Dynamic realm |
| `/async` | `authorizeAsync: true` | Callback-based async authorizer |
| `/custombody` | Custom response function | Dynamic 401 messages |
| `/staticbody` | Static string response | Fixed 401 body |
| `/jsonbody` | JSON response object | JSON 401 body |

### `tests/benchmarks/base64.bench.ts` — Base64 Decoding Benchmarks

Compares three base64 decoding strategies for basic-auth payloads:

| Method | Condition | Description |
|--------|-----------|-------------|
| `Uint8Array.fromBase64` + `TextDecoder` | Available (Node.js 20.6+) | Native API |
| `Buffer.from(base64).toString(utf-8)` | Available (Node.js) | Node Buffer API |
| `atob` + `Uint8Array.from` + `TextDecoder` | Always available | Fallback |

**Payloads**: Short username/password, common API-style credential, long token-like password.
